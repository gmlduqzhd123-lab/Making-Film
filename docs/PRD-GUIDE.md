# PRD에서 소개영상 만들기 — v1.1

## 사용 순서

1. 홈의 **PRD로 영상 만들기**, 또는 제작 화면 STEP 1의 **PRD 넣고 자동 작성**을 누릅니다.
2. 파일을 선택하거나 끌어다 놓습니다. 본문을 복사해 텍스트 입력란에 붙여 넣어도 됩니다.
3. 붙여넣었다면 **PRD 분석하기**를 누릅니다. 파일 업로드는 본문을 읽은 뒤 자동 분석합니다.
4. 추출한 이름·소개·URL·기능·대상·길이를 확인합니다. 내용이 없으면 기본값이나 추천을 표시하므로 필요한 부분을 고칩니다.
5. **이 PRD로 영상 만들기**를 누릅니다. 기존 작업을 보관하고 새 프로젝트를 만듭니다.
6. 9개 장면의 영상 초안을 재생하고 대본·자막·시간을 수정합니다. 이미지가 없어도 생성할 수 있습니다.
7. STEP 3 **화면 자료**에 실제 앱 스크린샷을 넣습니다. 이미지가 전혀 없던 PRD 프로젝트의 첫 업로드는 빈 장면에 순서대로 반복 배치됩니다. 수정한 장면 문구와 내레이션은 유지됩니다.
8. **JSON 저장**으로 원본을 보관하고, 영상 내보내기에서 HTML·ZIP·SRT·대본을 내려받습니다.

## 지원하는 입력

| 형식 | 처리 | 제한 |
|---|---|---|
| 붙여넣기 | 한국어·영어 항목, Markdown 제목·목록, 간단한 표 | 20자 이상, 20만 자 이하 |
| TXT / MD / MARKDOWN | 본문 읽기 | 2MB 이하 |
| JSON | 객체의 project/product/app 또는 최상위 정보 읽기 | 2MB 이하 |
| DOCX | `word/document.xml`의 문단·본문 텍스트 | 12MB 이하 |
| HWPX | `Contents/section*.xml`을 숫자 순서로 읽기 | 12MB 이하 |

파일에서 읽은 본문도 20만 자 이하여야 합니다. 문서 XML 본문은 합계 8MB까지 처리합니다. UTF-8, BOM 있는 UTF-16, EUC-KR 텍스트를 읽습니다. 암호화·손상·지원하지 않는 압축 형식의 문서는 안내 메시지를 표시합니다.

**PDF·HWP는 본문을 복사해 붙여 넣어 주세요.** DOCX/HWPX의 삽입 그림·서식·표 배치를 가져오지 않으며 스캔 문서 OCR도 제공하지 않습니다. ZIP 압축 해제를 지원하지 않는 브라우저에서는 TXT로 저장하거나 텍스트를 붙여 넣습니다. 최신 Chrome·Edge를 권장합니다.

## 잘 읽히는 PRD 예시

다음처럼 항목과 핵심 기능 목록을 나누면 추출이 쉬워집니다. 입력 창의 **입력 예시 넣기**도 사용할 수 있습니다.

```markdown
# 별빛 퀴즈 PRD
프로젝트명: 별빛 퀴즈
한 줄 소개: 학생들이 함께 퀴즈를 풀고 배움을 확인하는 교실 도구
웹앱 분야: 놀이
교과: 사회
학년: 3~4학년
대상: 교사, 학생
영상 길이: 60초

## 핵심 기능
- 주제별 퀴즈 선택
- 팀별 문제 풀이
- 결과 확인

## 향후 기능
- AI 문제 생성
```

핵심 기능은 앞의 5개까지 반영합니다. MVP와 핵심 기능이 함께 있으면 MVP를 우선하며 향후/Phase 2/Phase 3 목록은 제외합니다. 지원 영상 길이는 30·45·60·90초이며 문서에 하나의 길이가 없으면 60초를 추천합니다. 분야·대상·스타일을 찾지 못하면 추천 설정을 적용합니다. 실제 영상 문구는 기존 로컬 템플릿 엔진이 만듭니다.

JSON 예시:

```json
{
  "project": {
    "title": "별빛 퀴즈",
    "description": "학생들이 함께 퀴즈를 풀고 배움을 확인하는 교실 도구",
    "features": ["주제별 퀴즈 선택", "팀별 문제 풀이", "결과 확인"],
    "category": "놀이",
    "subject": "사회",
    "grade": "3~4학년",
    "audience": ["교사", "학생"],
    "duration": 60
  }
}
```

PRD JSON 입력은 설계 정보에서 초안을 만드는 용도입니다. 이미 편집한 `project.json`을 복원하려면 홈의 **프로젝트 불러오기**를 사용하세요.

## 확인해야 하는 내용

문서를 외부 AI에 보내지 않습니다. 제목·항목·목록을 분석하는 방식이라 문서 구조에 따라 일부 내용이 누락되거나 다른 문장을 소개로 고를 수 있습니다. 추출 결과를 확인하고 실제로 구현된 기능만 소개하세요. 추천 설정과 문구는 기능·교육 효과를 검증한 결과가 아닙니다.

전체 PRD 원문은 프로젝트 자동 저장에 포함하지 않습니다. 추출한 프로젝트 정보와 파일명·입력 글자 수·가져온 시각·방법·안내 메시지만 보관합니다. 파일을 업로드해도 브라우저 안에서 처리되며 서버 전송과 API 요청은 없습니다.

## 기존 Making-Film 저장소 업데이트

Codex에서 변경을 요청한 경우에는 완료한 소스를 연결된 GitHub 계정으로 직접 반영합니다. [GitHub 자동 반영 안내](GITHUB-WORKFLOW.md). 다음은 수동 업데이트를 선택한 경우의 방법입니다.

1. 제공한 **v1.1 전체 ZIP**을 압축 해제합니다.
2. GitHub의 `Making-Film` 저장소에서 **Add file → Upload files**를 엽니다.
3. 압축을 푼 폴더의 **내용물**을 올립니다. `index.html`, `css`, `js`, `docs` 등이 저장소 루트에 놓여야 합니다. ZIP 파일 자체나 상위 `yeopssam-video-maker` 폴더를 올리지 않습니다.
4. 같은 이름의 파일을 덮어쓰는 변경을 확인하고 커밋합니다. 새 `css/prd.css`, `js/modules/prdImporter.js`, `js/ui/prdImport.js`도 함께 올라가야 합니다.
5. Pages의 `main / (root)` 설정이 유지되어 있다면 재배포됩니다. **Actions**에서 배포 완료를 확인한 뒤 공개 페이지를 새로고침합니다.
6. 홈에 **PRD로 영상 만들기**가 보이는지 확인합니다. 예시 PRD를 넣고 분석·생성·재생까지 확인하세요. 이전 화면이 남으면 Ctrl+Shift+R로 새로고침합니다.

원본 JSON의 자동 저장과 앱 소스의 GitHub 반영은 별개입니다. 앱에서 제작한 영상 프로젝트는 이 브라우저에 저장하거나 JSON·HTML·ZIP으로 내보냅니다.
